# ZapretForAndroid

**Обход DPI-блокировок (YouTube, Discord и не только) на Android — без root, без сторонних бинарников, на чистом Kotlin.**

Порт идей [flowseal/zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube) и
[Sergeydigl3/zapret-discord-youtube-linux](https://github.com/Sergeydigl3/zapret-discord-youtube-linux) на
мобильную платформу. Вместо `nfqws`/`tpws` с их raw-сокетами приложение поднимает VPN-туннель и
реализует **собственный TCP/IP-стек в userspace** — это единственный способ получить побайтовый контроль
над тем, что и когда уходит в сеть, не имея прав суперпользователя.

Интерфейс — Material You (Monet): динамические цвета из обоев на Android 12+, шесть акцентных палитр
и светлая/тёмная тема на более старых версиях. Локализация: русский (по умолчанию) и английский.

## Почему без root

<a name="почему-без-root"></a>

Оригинальный `zapret` работает через `netfilter` (`NFQUEUE`, `divert`) или `raw`-сокеты: он перехватывает
**уже сформированные ядром пакеты** и правит их — меняет TTL, подделывает sequence-номера, дробит IP-пакеты,
добавляет IPv6-экстеншены, шлёт RST. Всё это требует `CAP_NET_ADMIN`, то есть root.

Android без root даёт приложению только один инструмент: `VpnService` + TUN-устройство. Трафик приходит
туда как IP-пакеты, а обратно мы обязаны отдать **целый, корректный поток** — ядро само соберёт его в
сегменты и добавит заголовки. Подделать TTL или seq в чужом пакете нельзя.

Поэтому приложение делает другое: оно **само играет роль сервера** для локальных приложений. Мы отвечаем
на SYN, ведём рукопожатие, принимаем байты клиента и **сами открываем настоящее соединение наружу**.
А значит — сами решаем, какими порциями и с какими паузами эти байты писать в сокет. Для DPI-фильтра
это выглядит как обычное соединение, но граница между фрагментами ClientHello оказывается там, где нужно нам.

## Возможности

**Ядро**
- Собственный TCP/IP-стек: IPv4 и IPv6, рукопожатие с window scaling, корректный MSS-кламп,
  go-back-N ретрансмиссии (RTO 800 мс → 16 с, fast retransmit по 3 dup-ACK), FIN/RST, backpressure в обе стороны.
- Движок десинхронизации TLS ClientHello и HTTP `Host:` с настраиваемой точкой разбиения, задержкой
  между фрагментами и переупаковкой TLS-записей.
- Цепочки правил (`--new`): своя маска портов, свой источник хостов, своя стратегия, приоритет по порядку.
- UDP-релей, отдельная блокировка QUIC (UDP/443), режимы «релей / блокировать фильтруемые / блокировать всё».
- Статистика в реальном времени: соединения, трафик, сколько пакетов десинхронизировано, DNS-запросы, аптайм.
- Журнал последних соединений (хост, порт, применённая техника) и кольцевой лог с фильтрами по подсистемам.

**Сети и DNS**
- DNS: системный, свой список серверов, **DoH** и **DoT**. DoH идёт через защищённый от туннеля сокет
  (`protect()`) — иначе он бы зациклился сам на себя.
- Перехват всех запросов на порт 53 (защита от подмены ответов провайдером), кэш с настраиваемым TTL,
  блокировка рекламных доменов, проброс не-A/AAAA-запросов.
- **Таблица hosts внутри подключения**: свои пары «IP → домен», которые применяются до любого резолвера.
  Это и есть «изменение hosts в подключении» — можно перенаправить домен на любой адрес, не трогая систему.
- Списки `hostlist` / `hostlist-exclude` / `ipset` / `ipset-exclude` с встроенными наборами
  Google/YouTube, Discord, General и полноэкранным редактором (вставка из буфера, отправка наружу).

**Система**
- Material You: динамические цвета (Android 12+), шесть акцентов, светлая/тёмная/системная тема.
- Плитка в шторке быстрых настроек — включение одним свайпом.
- Автозапуск после перезагрузки (если разрешение на VPN уже выдано).
- Область действия: весь трафик / только выбранные приложения / все кроме выбранных (Android 10+).
- Чек-лист готовности на главном экране: уведомления, оптимизация батареи, Always-on VPN.
- Экспорт/импорт всей конфигурации в JSON, сброс к заводским.
- Уведомление о неожиданной остановке туннеля: молчаливая остановка выглядела
  как «обход работает», хотя трафик уже шёл мимо.
- Горячая перезагрузка: смена MTU, IPv4/IPv6, области приложений перезапускает туннель;
  остальные настройки подхватываются **без разрыва** текущих соединений.

## Быстрый старт

1. Соберите и установите APK (см. [Сборка](#сборка)).
2. Запустите приложение. На главном экране нажмите большую кнопку питания.
3. Android покажет системный диалог **«Разрешить подключение к VPN?»** — нажмите «Разрешить».
   Это делается один раз, дальше разрешение сохраняется.
4. Пройдите чек-лист: разрешите уведомления, отключите оптимизацию батареи, при желании включите
   Always-on VPN в системных настройках — иначе производитель смартфона может убить туннель в фоне.
5. Выберите профиль (по умолчанию — «Комбинированный»: YouTube + Discord) и проверьте видео.

Если не работает: откройте **«Ещё» → Журнал** и посмотрите, что происходит. Обычно причина одна
из трёх — провайдер требует другую точку разбиения, включён QUIC у клиента, или DPI ожидает иной
набор портов. Быстрый способ снять вопрос «а работает ли вообще обход» — **«Ещё» → «Автоподбор
стратегии»**: он честно прогоняет кандидатов настоящим TLS-рукопожатием и применяет победителя.

## Сборка

Требуется JDK 17 + Android SDK с платформой 35 (или Android Studio Ladybug и новее).

```bash
git clone <этот репозиторий>
cd ZapretForAndroid
```

Gradle Wrapper лежит в репозитории (`gradlew`, `gradlew.bat`,
`gradle/wrapper/gradle-wrapper.jar`), поэтому установленный Gradle не нужен —
используется ровно та версия, что и в CI (8.9).

```bash
./gradlew assembleDebug        # отладочный APK
./gradlew assembleRelease      # подписанный APK с R8
./gradlew testDebugUnitTest    # интеграционные тесты пакетного тракта
```

Готовый отладочный APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

| Параметр | Значение |
|---|---|
| minSdk | 24 (Android 7.0) |
| targetSdk / compileSdk | 35 |
| Kotlin | 2.0.21 |
| AGP | 8.7.2 |
| Compose BOM | 2024.10.01 |
| JVM | 17 |

### Подпись

Релиз подписывается **зафиксированным ключом** `keystore/release.p12`
(PKCS#12, alias `zapret`, срок действия 30 лет, параметры — в
`keystore/signing.properties`). Ключ один и тот же для локальной сборки и для
CI, поэтому новый APK ставится поверх старого без удаления приложения и без
потери настроек.

> Ключ намеренно лежит в публичном репозитории — иначе подпись «поехала» бы
> между сборками. **Для Google Play он не годится**: сгенерируйте свой
> (Android Studio → Build → Generate Signed Bundle / APK) и перекройте
> параметры флагами `-PZAPRET_STORE_FILE=… -PZAPRET_STORE_PASSWORD=…
> -PZAPRET_KEY_ALIAS=… -PZAPRET_KEY_PASSWORD=…` или переменными окружения
> с теми же именами. Если `release.p12` отсутствует, релиз автоматически
> откатывается на debug-ключ — сборка не падает.

### Готовые APK

**Релизы** — вкладка **Releases**. Каждый тег вида `v1.0.0` запускает
`.github/workflows/release.yml` и публикует подписанный APK
`zapret-v1.0.0.apk`. Это постоянные файлы, в отличие от артефактов Actions.

**Артефакты сборки** — каждый пуш собирает `.github/workflows/build.yml`:
`assembleRelease` (подписанный, с R8) и `assembleDebug`. Вкладка **Actions** →
последний запуск → **Artifacts** → `zapret-apk`. Артефакты живут 30 дней,
так что для постоянной ссылки нужен релиз по тегу.

В логе сборки шаг **Report signing** печатает результат проверки подписи
каждого APK — им можно убедиться, что подпись валидна и что схемы на месте.

Чтобы выпустить релиз:

```bash
git tag v1.0.0
git push origin v1.0.0
```

### Тесты

`./gradlew testDebugUnitTest` — 72 теста пакетного тракта на JVM, двенадцать классов:

| Класс | Что проверяет |
|---|---|
| `TcpRelayTest` | полное TCP-соединение через `TcpStack` (обе стороны, IPv4 и IPv6), UDP-релей, контрольные суммы против независимого эталона, кодек DNS |
| `DesyncTest` | где именно проходит граница между фрагментами `ClientHello` |
| `EndToEndTlsTest` | настоящий TLS-сервер: разбитое рукопожатие доходит и сервер отвечает |
| `HandshakeAssemblyTest` | поведение на укороченном `ClientHello` |
| `HandshakeAssemblyTimeoutTest` | неполное рукопожатие не держит соединение минутами |
| `HostListCoverageTest` | встроенные списки покрывают настоящие имена хостов YouTube |
| `PresetCoverageTest` | стратегия реально применяется к CDN-хостам YouTube и портам Discord |
| `AutopilotCandidatesTest` | каждый кандидат автоподбора даёт рабочее разбиение |
| `QuicBlockingTest` | блокируются все формы QUIC Initial и не рвётся 1-RTT |
| `RegressionsTest` | дефекты, найденные при проверке на устройстве |
| `SniCaseMixTest` | смена регистра меняет ровно один байт внутри домена второго уровня, длина и разбираемость ClientHello сохраняются, приём выключен во всех профилях |
| `PoisonRecordTest` | подстава синтаксически корректна, но приём обязан оставаться выключенным во всех профилях и в автоподборе — он ломает рукопожатие |

CI прогоняет их до сборки APK: поломка сегментации или контрольных сумм видна
сразу, а не после установки на телефон.

Границы фрагментов проверяются на `DesyncPlan.writes` — это ровно те записи,
которые стек делает в сокет по отдельности. По проводу их не измерить: `recv()`
не обязан совпадать с границами TCP-сегментов.

## Стратегии

<a name="стратегии"></a>

**Общая стратегия** задаёт поведение по умолчанию: режим десинхронизации, точки разбиения, задержку,
переупаковку TLS-записей, `--wssize`, количество обрабатываемых чанков (`cutoff`).

**Правила** — аналог блоков, разделённых `--new` в `.bat`-файлах zapret. Каждое правило имеет:
- маску TCP- и UDP-портов (пустая маска = правило не применяется к этому протоколу);
- источник хостов: любой / `--hostlist` / общий список / Google / Discord / inline-домены;
- список исключений (`--hostlist-exclude`);
- собственную стратегию.

Правила проверяются сверху вниз, срабатывает первое подходящее. Порядок меняется стрелками в списке.

Пример рабочей цепочки для YouTube:

```
Правило 1: tcp=443  --hostlist=Google   multisplit @ midsld, delay 2 ms
Правило 2: tcp=80   --hostlist=Google   hostfakesplit
Правило 3: udp=443  любой хост          блок (QUIC)
```

### Точки разбиения

| Токен zapret | Что означает |
|---|---|
| `1` | первый байт полезной нагрузки уходит отдельным сегментом |
| `midsld` | середина **домена второго уровня** в SNI |
| `sniend` | сразу после конца SNI |
| `middle` | середина TLS-записи ClientHello |
| `custom` | произвольное смещение в байтах (слайдер 1–1500) |

Точек можно выбрать несколько — тогда применяется `multisplit` и фрагментов будет N+1.
Задержка между фрагментами (`--split-delay`, расширение приложения) помогает, когда провайдерский
DPI склеивает сегменты обратно: по умолчанию `tcp_autocorking` в Linux может объединить две быстрые
записи в один пакет, поэтому 1–2 мс иногда решают всё.

**Почему именно `midsld`, а не середина SNI.** Разбивать нужно внутри домена второго
уровня — там, где DPI ищет домен. Это видно на реальных именах YouTube:

```
середина SNI:  rr12---sn-4g5edns|e.googlevideo.com   ← разрыв в случайном префиксе, бесполезно
midsld:        rr12---sn-4g5ednse.googl|evideo.com   ← разрыв внутри домена, работает
```

На коротких именах вроде `www.google.com` обе точки совпадают, поэтому разница
проявляется только на CDN-хостах — то есть ровно там, где идёт видео.

### Отравление разбора DPI подставной записью — НЕ РАБОТАЕТ

Приём из разбора байткода рабочего приложения (`--fake`, `--fake-sni`,
`Os.setsockoptInt` с `IP_TTL`). Проверен и **отвергнут**: он ломает рукопожатие.

Идея была верной: перед настоящим ClientHello уходит целая посторонняя
TLS-запись, сервер её не считает началом рукопожатия, а DPI разбирает поток
заново и до настоящего ClientHello не доходит. На поверхности всё сходилось —
проверка «пришёл ли байт `0x16` в ответ» давала 10 из 10.

Проверка была неверной. Полное рукопожатие с валидацией сертификата:

| вариант | результат |
|---|---|
| подставная запись + настоящий `www.youtube.com` | `INAPPROPRIATE_FALLBACK` |
| подставная запись + настоящий `www.google.com` | `INAPPROPRIATE_FALLBACK` |

Сервер отвечает на **подставу** — она целый ClientHello — и присылает сертификат
для `www.google.com`. Клиент просил `www.youtube.com`, значит рукопожатие падает.
Байт `0x16` в моей проверке приходил в ответ на подставу, а не как признак
рабочего соединения, поэтому приём и выглядел успешным. Ломается всё, включая
Google, который до его включения работал.

Почему TTL не спасает. В zapret фальшивый пакет гаснет по пути и до сервера не
доходит — но там работают с пакетами напрямую. Обычный TCP-сокет переотправит
неподтверждённую подставу через секунду уже с нормальным TTL, и сервер получит
её в любом случае, уже посреди рукопожатия.

Поэтому приём есть в коде, но **выключен везде**: в профилях его нет, в
автоподборе его нет, а тесты требуют, чтобы он оставался выключенным. Тонко
настраивать нечего — он не пригоден без работы с пакетами.

### Смена регистра в имени хоста (`--hostcase`)

Разбиение сегментов помогает не на всех фильтрах. Найденные здесь пересобирающие
фильтры склеивают фрагменты обратно без ограничения по времени — проверено задержками
от 0 до 2500 мс, а также разбиением рукопожатия по границам TLS-записей: склеивается всё.

На таких фильтрах работает другое: **имя хоста регистронезависимо** (RFC 6066 для SNI,
RFC 7230 для `Host`), а большинство фильтров ищут домен обычной подстрокой. Достаточно
изменить регистр одной буквы внутри домена второго уровня — и подстрока перестаёт
совпадать, тогда как сервер и проверка сертификата разницы не видят.

```
www.youtube.com        → www.YouTube.com      домен внутри сломан, подстрока не ищется
wWw.youtube.com        → не помогает          домен «youtube.com» остался читаемым
www.youtube.coM        → не померает          то же
```

Измерено на реальном фильтре байтами, которые производит само приложение,
по кругу с вариантом без приёма для контроля:

| вариант | ServerHello |
|---|---|
| строчными, одним куском | 0 из 6 |
| строчными, три сегмента `1,midsld` | 0 из 6 |
| **смена регистра, одним куском** | **6 из 6** |
| смена регистра + разбиение по первому байту | 6 из 6 |
| смена регистра + разбиение `1,midsld` | 5 из 6 |
| смена регистра + разбиение только по `midsld` | 0 из 6 |

Обратите внимание на последнюю строку: **разбиение внутри домена приём портит.**
Разрыв попадает ровно в ту строку, которую смена регистра ломает, и фильтр получает
её обратно склеенной. Поэтому в автоподборе сплошной поток проверяется первым, а
разбиение по середине домена — последним.

Меняется именно домен второго уровня, потому что он попадает в списки блокировки.
Меняется **одна** буква, а не всё имя: Cloudflare отвечает только на канонический регистр
и молча рвёт соединение на `www.Cloudflare.com`, тогда как `www.Cloudflare.com` → нет.
Длина байтов не меняется, поэтому длины в полях TLS править не нужно.

**Приём включается только на правилах с источником Google, не глобально.** Замеры
с устройства, где стоит настоящий фильтр, по два прогона на каждый хост:

| хост | строчными | со сменой регистра |
|---|---|---|
| `www.youtube.com` | блок | **проходит** |
| `youtubei.googleapis.com` | блок | **проходит** |
| `www.google.com` | проходит | проходит |
| `www.cloudflare.com` | проходит | **ломается** |
| `discord.com` | блок | блок |

Cloudflare отвечает только на канонический регистр и молча рвёт соединение. Поэтому
приём нельзя включать глобально — сломался бы и Discord, и любой сайт за Cloudflare.
Общая настройка профиля остаётся выключенной, а приём живёт в правилах с источником
Google; его можно и снять вручную.

Применяется до разбиения: если сначала разрезать, а потом поменять регистр, фильтр всё
равно увидит домен в склеенном потоке — обе операции по отдельности бесполезны.

## Парсер командной строки zapret

<a name="парсер-командной-строки-zapret"></a>

**«Ещё» → «Аргументы zapret»** принимает строку вида:

```
--filter-tcp=443 --hostlist=list-google.txt --ip-id=zero --dpi-desync=fake,multisplit \
--dpi-desync-split-seqovl=681 --dpi-desync-split-pos=1 --dpi-desync-fooling=ts \
--dpi-desync-repeats=8 --wssize=6:1 --new --filter-udp=443 --dpi-desync=fake
```

Разбор выдаёт четыре списка: **применено**, **проигнорировано** (root-only, с объяснением),
**неизвестно**, **ошибки**. Обратная операция — «Сгенерированная строка» — показывает текущую
конфигурацию в синтаксисе zapret; её можно скопировать и сравнить с оригиналом.

Поддерживаются: `--dpi-desync` (`split`, `multisplit`, `tlsrec`, `multisplit,tlsrec`, `hostfakesplit`, `none`),
`--dpi-desync-split-pos`, `--dpi-desync-tlsrec`, `--dpi-desync-cutoff`, `--dpi-desync-any-protocol`,
`--wssize=P:W`, `--filter-tcp`, `--filter-udp`, `--wf-tcp`, `--wf-udp`, `--hostlist`, `--hostlist-exclude`,
`--hostlist-domains`, `--ipset`, `--ipset-exclude`, `--new`, а также собственное расширение `--split-delay=N`
и `--rule-name=…`.

## Списки и hosts

<a name="списки-и-hosts"></a>

**«Ещё» → «Списки»** — пять вкладок, каждая это файл в `filesDir/lists/`:

| Вкладка | Файл | Аналог в zapret |
|---|---|---|
| Хосты | `hostlist.txt` | `--hostlist` |
| Исключения | `exclude.txt` | `--hostlist-exclude` |
| IP-сети | `ipset.txt` | `--ipset` |
| IP-исключения | `ipset-exclude.txt` | `--ipset-exclude` |
| **hosts** | `hosts.txt` | нет аналога |

Формат `hosts.txt` — как в системном файле, комментарии через `#`:

```
# перенаправить домен на свой адрес
185.199.108.153  youtube.com
93.184.216.34    example.com
# заблокировать
0.0.0.0          ads.example.net
```

Записи применяются **внутри туннеля**, на этапе разрешения имён, до обращения к любому DNS-серверу.
Это даёт максимум кастомизации: можно подменить адрес конкретного домена для конкретного соединения,
не имея root и не трогая системный `/etc/hosts` (который на Android всё равно read-only).
Список `0.0.0.0` используется как блок-лист — соединение до такого адреса не открывается.

Редактор полноэкранный, моноширинный, с вставкой из буфера обмена и отправкой файла наружу.
Кнопка «Загрузить встроенные» возвращает наборы Google / Discord / General.

## DNS

Четыре режима:

- **Системный** — ответы приходят от DNS текущей сети (через прозрачный проброс запроса).
- **Свой список** — любые серверы, по одному в строке, порт опционален (`1.1.1.1:5353`).
- **DoH** — пресеты Google, Cloudflare, Quad9, AdGuard, Yandex, Comss, NextDNS или свой URL.
- **DoT** — TLS 1.2+ на порт 853.

Дополнительно:
- **Перехват порта 53** — все DNS-запросы приложений идут через наш резолвер, даже если приложение
  жёстко прописало `8.8.8.8`. Именно это защищает от подмены ответов провайдером.
- **Защита от подмены** — всегда резолвить через настроенный сервер, игнорируя адреса из запроса.
- **Кэш** с настраиваемым TTL (30–3600 с).
- **Блокировка рекламы** по доменам.
- Кнопка **«Проверить»** показывает, какой адрес вернёт текущая конфигурация для `www.google.com`.

## Архитектура

<a name="архитектура"></a>

```
┌─────────────────────── приложение-клиент ──────────────────────┐
│  SYN ──► TUN ──► ZapretVpnService ──► TcpStack                 │
│                          │                 │                   │
│                    parseIp/TCP/UDP    TcpConnection            │
│                          │            (наш userspace-стек)     │
│                          │                 │                   │
│                   UDP/53 ─► DnsHandler     │ SYN-ACK, ACK,     │
│                            │  hosts →     │ window scaling,   │
│                            │  cache →     │ ретрансмиссии     │
│                            │  DoH/DoT     │                   │
│                            ▼              ▼                   │
│                       ответ клиенту   StrategyResolver         │
│                                       (правила --new,          │
│                                        hostlist/ipset)         │
│                                            │                   │
│                                       DesyncEngine             │
│                                       (split / tlsrec /        │
│                                        hostfakesplit)          │
│                                            │                   │
│                                  protect()ed Socket ───────────┼──► интернет
└────────────────────────────────────────────────────────────────┘
```

Ключевые решения:

- **TUN, а не прокси.** Прозрачный перехват на уровне IP: приложения ничего не настраивают,
  работает любой софт, включая тот, который игнорирует системный прокси.
- **Свой стек, а не `SSLSocket`.** Только владея клиентской стороной TCP, мы контролируем границы
  записей в upstream-сокет. `TCP_NODELAY` + явная задержка между фрагментами = предсказуемое разбиение.
- **`protect()` на всех исходящих сокетах** — иначе наш собственный трафик вернулся бы в туннель и
  зациклился. DoH/DoT строятся вручную поверх защищённого сокета, без `OkHttp`/`HttpURLConnection`.
- **Виртуальный DNS `10.211.0.2`** при адресе туннеля `10.211.0.1/32` и маршруте `0.0.0.0/0`.
  Адрес самого туннеля для DNS использовать нельзя — ядро отвечает на него локально.
- **Горячая перезагрузка.** Сигнатура конфигурации (MTU, IPv4/IPv6, область приложений, профиль)
  сравнивается на каждом пакете; изменение этих полей требует пересоздания `VpnService.Builder`,
  всё остальное подхватывается на лету.
- **Backpressure в обе стороны.** Очередь отправки ограничена `sendBufferKb`, приём — 1 МБ
  (при превышении advertise zero window), количество одновременных соединений — `maxConnections`.

Подробнее: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Известные ограничения

- **Только TCP и UDP.** ICMP не обрабатывается, поэтому `ping` через туннель не ходит.
- **Нет IPv6-фрагментации и экстеншенов** — см. матрицу возможностей.
- **IPv6 включается сам.** Если у физической сети нет глобального IPv6-адреса, маршрут `::/0`
  не объявляется: иначе приложения получали бы AAAA, пробовали бы v6 и висели на таймауте
  подключения — сеть выглядела бы «есть, но всё очень медленно». Фактическое состояние видно
  в журнале при подъёме туннеля.
- **MTU.** Значение выше реального MTU канала приведёт к «чёрной дыре» на крупных пакетах.
  Слайдер MSS-клампа в «Ещё → Сеть» лечит это без изменения MTU.
- **Производительные OEM-прошивки** (Xiaomi, Huawei, Samsung, Oppo) агрессивно убивают фоновые
  сервисы. Без отключения оптимизации батареи и/или Always-on VPN туннель может молча умереть.
- **Автозапуск после перезагрузки** срабатывает, только если разрешение на VPN уже выдано и
  система не запрещает фоновый старт foreground-сервиса.
- **Приложения с certificate pinning** могут отказаться работать через наш стек, если стратегия
  задевает их порты — исключите их в «Ещё → Сеть → Область действия».
- **DPI, склеивающий сегменты с минимальной задержкой.** Если провайдерский фильтр ждёт
  паузу между сегментами меньше нашей, он склеит `ClientHello` обратно и прочитает домен.
  В этом случае поднимите задержку между фрагментами (в профиле «Максимальный» она уже 3 мс,
  автоподбор пробует и 40 мс) либо включите «Медленный старт окна» (`--wssize`).
- **Разбиение работает по имени из ClientHello.** Если клиент не отдаёт SNI (например,
  соединение открыто сразу на IP), применяется обратный кэш DNS, а при его отсутствии —
  стратегия по порту. На таких соединениях домен не разбить, и обход сработает слабее.
- **Отравление DPI подставной записью непригодно без root.** Приём есть в коде,
  но выключен везде: сервер отвечает на подставу и присылает сертификат чужого
  домена, рукопожатие падает. Подробный разбор — в разделе про отравление.
- **Смена регистра имени хоста непригодна для Cloudflare.** На фильтрах с подстрочным
  поиском домена она обходит блокировку, но Cloudflare отвечает только на канонический
  регистр. Поэтому включена на правилах с источником Google и выключена глобально.
